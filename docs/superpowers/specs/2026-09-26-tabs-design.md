# Tabs: составной компонент Dreadnought

Статус: согласованное проектное решение; реализация ещё не начата.

## Задача и границы

`Tabs` нужен лендингу для переключения примеров по слоям библиотеки и документации — для разных вариантов одного примера. Панель должна принимать произвольное содержимое. Компонент проверяет, что составное взаимодействие можно реализовать без дублирования поведения между тремя слоями.

Первая версия — горизонтальные вкладки с заранее доступным содержимым. Асинхронную загрузку, вертикальную ориентацию, закрытие и перестановку вкладок, ручное подтверждение выбора и импорт из массива `items` не добавляем. При дорогой загрузке панелей автоматическую активацию потребуется пересмотреть отдельно.

## Публичный API

```tsx
<Tabs defaultValue="ready" onValueChange={handleChange}>
  <Tabs.List aria-label="Способ использования">
    <Tabs.Tab value="ready">Готовый компонент</Tabs.Tab>
    <Tabs.Tab value="adapter">Адаптер</Tabs.Tab>
    <Tabs.Tab value="core" disabled>Логика</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panel value="ready">Любой React-контент</Tabs.Panel>
  <Tabs.Panel value="adapter">Другой контент</Tabs.Panel>
  <Tabs.Panel value="core">Недоступная вкладка</Tabs.Panel>
</Tabs>
```

`Tabs` — корень; `List`, `Tab`, `Panel` — его публичные части. `value` — непустая строка, уникальная в пределах одного набора. Для выбора требуется либо `defaultValue` (внутреннее состояние), либо `value` (управляемый режим); оба одновременно не передаются. `onValueChange(value)` вызывается при запросе смены вкладки, но не при первоначальном показе. В управляемом режиме родитель передаёт новое `value` обратно. `className` каждой части относится к её собственному DOM-элементу. `List` принимает доступное имя через `aria-label` или `aria-labelledby`.

Выбранная вкладка должна существовать и не быть `disabled`. Несовпадающие или повторяющиеся значения считаются ошибкой использования API; компонент не переключается на другую вкладку молча. Каждой вкладке соответствует одна панель с тем же `value`.

## Поведение и доступность

- `List` имеет `role="tablist"`; вкладки — нативные `button type="button"` с `role="tab"`, `aria-selected`, `aria-controls` и управляемым `tabIndex`; панели — `role="tabpanel"` с `aria-labelledby`. Идентификаторы пар стабильны в SSR и при гидратации.
- При входе клавишей Tab фокус получает выбранная вкладка. Стрелки влево/вправо переводят фокус и сразу выбирают предыдущую/следующую доступную вкладку с переходом через край. Home/End выбирают первую/последнюю доступную. `disabled` пропускается; Enter/Space сохраняют обычную активацию кнопки. Вертикальные стрелки не перехватываются.
- Неактивные панели остаются в DOM, но скрыты атрибутом `hidden`: так сохраняется их локальное состояние и работают связи `aria-controls`. Активная панель получает `tabIndex={0}`, чтобы пользователь мог перейти к её содержимому. Вкладка не навязывает содержимому семантику заголовка.
- При нажатии на вкладку она выбирается и получает фокус. В контролируемом режиме `onValueChange` сообщает намерение; если родитель не обновил `value`, отображаемый выбор остаётся прежним.
- Состояние `disabled` блокирует клик и клавиатурный выбор. Если доступных вкладок нет, клавиатурная навигация ничего не меняет.

Поведение соответствует [WAI-ARIA Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/). Автоматическая активация подходит для локальных, заранее доступных панелей, ради которых компонент сейчас нужен.

## Ответственность слоёв

1. `core/components/Navigation/Tabs` содержит `TabsCore` и чистые правила выбора следующего доступного значения. Здесь нет React, DOM и CSS. Общий `behaviors/` не пополняем до появления второго реального потребителя правил.
2. `adapters/react/src/Navigation/Tabs` содержит `TabsAdapter` с составными `List`, `Tab`, `Panel`, React-контекст для выбранного значения, регистрацию вкладок в порядке DOM, refs, события, фокус и ARIA-связи. Это слой 2; ни стили, ни тема сюда не импортируются. React-логика, нужная для самостоятельной сборки, экспортируется через `@dreadnought/react/logic`, а не через путь к исходнику.
3. `ui/src/presentation/Navigation/Tabs` содержит CSS Module и карту классов, `ui/src/adapters/react/components/Navigation/Tabs` — тонкие оформленные фасады `Tabs` и его частей. Они используют части `TabsAdapter`, не повторяя поведение. Токены и типографика располагаются в `themes/default` по принятой структуре `Navigation/Tabs`.

Импорт `TabsAdapter` из `@dreadnought/react/unstyled` не подключает оформление. Импорт `Tabs` из `@dreadnought/ui/react` предоставляет стандартное оформление без отдельного CSS-импорта. Корень и каждая значимая часть получают собственные `className` и компонентные токены; пользователь может менять оформление без обращения к внутренней вложенности. Стили остаются в `@layer dreadnought`.

## Проверка результата

- Тесты `core`: поиск следующей доступной вкладки, переход через край, отсутствие доступной вкладки.
- Тесты адаптера: управляемый и неуправляемый режимы, клик, клавиатура, disabled, связь вкладок с панелями, `hidden`, фокус и стабильность API частей.
- Тесты UI и темы: классы применяются только к оформленному варианту, слои стилей и токены работают без влияния на `TabsAdapter`.
- Пример и интерактивная история Storybook для обоих способов использования; документация объясняет связь `value` и ограничение автоматической активации.
- Сборка, типы, тесты и публичные импорты проходят в существующем workspace.
