# Варианты компонентов, маркеры и иконки

## Цель

Привести Button, Badge, Input и Tabs к единому округлому визуальному языку тёмной темы; добавить переиспользуемые Mark и Icon без привязки публичного API к Ant Design. Изменения не затрагивают поведение кнопок, полей и вкладок.

## Публичный API

- `Button.variant`: `primary` (по умолчанию), `secondary`, `outlined`, `ghosted`. Работает одинаково для кнопки и ссылки (`href`). Существующие `icon`, `iconPosition`, `loading`, `disabled` сохраняются.
- `Badge.appearance`: `solid` (по умолчанию), `outline`, `ghosted`. Существующие `target`, `icon`, `iconPosition` сохраняются. Единственный проп `icon` принимает либо `<Mark />`, либо `<Icon />`, либо другое React-содержимое; без него ничего не рисуется. `children` остаётся текстом/содержимым Badge.
- `Mark.shape`: `circle` (по умолчанию) или `square`; `color?: string` принимает CSS-цвет, включая `var(--dreadnought-color-status-success)`. Без `color` маркер наследует `currentColor`. Mark декоративен по умолчанию.
- `Icon.name`: собственное стабильное имя, первоначально `eye`, `eye-off`, `search`, `check`, `close`. На старте React-реализация сопоставляет их с отдельными SVG-иконками пакета `@ant-design/icons`. Пропсы потребителя не раскрывают типы Ant Design. Icon декоративен по умолчанию; для самостоятельной смысловой иконки поддерживается `aria-label`.
- `Input type="password"`: пользователь видит иконку `eye`/`eye-off`, а не надпись на кнопке. Существующий `passwordVisibilityLabels` остаётся для `aria-label` и локализации. Остальные типы Input не получают кнопку видимости.

## Слои и зависимости

- Новых сущностей `core` нет: Mark и Icon не имеют независимого поведения, а текущая логика Button/Input остаётся в первом слое.
- Во втором слое React-адаптеры Mark/Icon отвечают за HTML-структуру и доступность без CSS. `InputAdapter` получает необязательный `passwordVisibilityContent?: { show: ReactNode; hide: ReactNode }`: `show` отображается при скрытом пароле, `hide` — при открытом. Если проп не передали, неоформленный адаптер сохраняет текстовую кнопку. Второй слой не импортирует UI, тему или `@ant-design/icons`.
- В третьем слое `Mark` добавляет оформление к `MarkAdapter`, `Icon` выбирает SVG по имени и оформляет `IconAdapter`. Оформленный `Input` передаёт `eye`/`eye-off` в `InputAdapter`. Публичный `IconName` экспортируется из независимого от React входа `@dreadnought/ui`; реестр соответствий Ant Design существует только в React-входе `@dreadnought/ui/react`. Проп `name` передаётся до фасада Icon и не требует изменения второго слоя при смене набора SVG.
- Для будущего веб-фреймворка потребуется его адаптер разметки и отображение тех же `IconName` на доступные SVG. Общие CSS Modules, токены и публичные имена при этом сохраняются.
- Папки Mark/Icon размещаются в семействе `DataDisplay` во втором и третьем слоях; тесты повторяют структуру `src`. Каждый новый каталог компонента имеет локальный `index.ts`, семейный и корневой экспорты остаются короткими.

## Визуальные правила

- Глобальный `border-radius-pill` задаётся один раз в теме. На него ссылаются радиусы всех вариантов Button и Badge, а также списка и вкладок Tabs. Контур не меняет внешний радиус Badge.
- `Button primary`: белая поверхность, тёмный текст; hover — светло-серый. `secondary`: серый темнее текущего, светлый текст. `outlined`: прозрачная поверхность, заметная граница и светлый текст. `ghosted`: прозрачная поверхность без постоянной границы, светлый текст; hover добавляет тёмную поверхность. Каждый вариант получает компонентные токены цветов для normal/hover и понятный focus-visible. Disabled/loading остаются различимыми.
- `Badge ghosted`: без фона и границы, только содержимое и необязательный `icon`. `solid` и `outline` сохраняют собственные цвета, но имеют одинаковую геометрию-пилюлю. Mark имеет отдельные токены размера и формы; его цвет задаётся через публичный проп или наследуется.
- `Input`: при `:focus-within` меняется цвет существующей границы, без дополнительного outline. Невалидное поле сохраняет цвет ошибки и в фокусе. Кнопка видимости остаётся в общей оболочке поля; её иконка центрируется и наследует текстовый цвет.
- `Tabs`: и список, и каждая вкладка имеют радиус-пилюлю; существующая тёмная палитра и выбранное состояние сохраняются.
- Все значения оформлений задаются через токены темы и CSS Modules. Глобальные числовые шкалы/роли переиспользуются; значения конкретных вариантов находятся в токенах компонентов. `!important`, глобальные селекторы компонентов и инлайновые стили, кроме публичного цвета Mark, не вводятся.

## Проверка и границы задачи

- Тесты: новые варианты Button/Badge для кнопки, ссылки и overlay; Mark формы и цвет; Icon отображение каждого имени и доступность; парольный Input переключает тип и иконку при сохранении `aria-label`; фокус Input без двойной обводки; целостность токенов.
- Storybook: истории для всех вариантов Button/Badge, Mark и Icon, парольного Input, обновлённые Tabs; визуальная проверка normal/hover/focus/disabled/invalid на графитовом фоне. Затем полные тесты, типизация и сборка.
- Не добавляем произвольную загрузку SVG, полный каталог Ant Design, отдельную светлую тему или изменения поведения core. Новые имена иконок добавляются в контролируемый реестр по мере появления сценариев.
