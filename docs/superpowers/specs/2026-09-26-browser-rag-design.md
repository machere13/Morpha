# RAG-помощник документации без сервера модели

Статус: проектное решение для согласования. Реализация ещё не начата.

## Цель и границы

Помощник помогает разработчику понять опубликованные возможности Dreadnought и найти способ их применения. Успешный ответ кратко объясняет возможность, при необходимости показывает публичный импорт или пример и ведёт к конкретному разделу документации. Ответы о планах, внутренних решениях и ещё не выпущенном API исключены.

Лендинг, сайт-представление и документация размещаются как статические сайты на Timeweb Cloud. Генерация ответа выполняется в браузере посетителя, поэтому постоянно работающий сервер модели, база векторов и платный API не входят в первую версию. RAG относится к приложению документации и не добавляет зависимостей в runtime UI-библиотеки.

## Источник знаний и публикация

Единственный корпус помощника — страницы, реально включённые в опубликованную версию сайта документации. На этапе сборки сайт формирует манифест из публичных страниц с полями `id`, `title`, `url`, `section`, `version`, `text` и `code`. Разделы получают устойчивые ссылки. В манифест не попадают `docs/plan.md`, архитектурные планы, проектные спецификации, исходники, тесты и черновики. Существующие описания компонентов и действий можно использовать как исходный материал для страниц, но сами файлы репозитория не считаются опубликованными автоматически.

Разбиение идёт по смысловым разделам и примерам кода, с сохранением заголовка страницы и иерархии разделов. Пример кода остаётся целым. Сборка проверяет уникальность `id`, существование URL и непустой текст. При выпуске новой версии сайта индекс пересобирается вместе с ней; индекс текущей версии не смешивается с будущими или архивными страницами.

## Поиск и ответ

Поиск работает локально по статическому индексу. Первая версия использует полнотекстовое ранжирование с повышенным весом названий компонентов, точных имён API, заголовков и путей импорта. Это соответствует небольшому корпусу и запросам вида «умеет ли Input показывать пароль?» или «как подключить тему?». Векторный индекс добавляется только если проверка реальными вопросами обнаружит пропуски, которые нельзя устранить настройкой текстового поиска.

Для каждого вопроса поиск отдаёт несколько наиболее подходящих фрагментов. Интерфейс сразу показывает их как обычные результаты с заголовком и ссылкой. Если релевантного фрагмента нет, помощник сообщает, что подтверждения в опубликованной документации не найдено, и не запускает генерацию.

После явного действия пользователя браузер загружает модель через [WebLLM](https://github.com/mlc-ai/web-llm) и передаёт ей вопрос вместе с найденными фрагментами, их идентификаторами и инструкцией отвечать только по ним. Для первой версии выбран [Qwen3-1.7B в сборке WebLLM](https://huggingface.co/mlc-ai/Qwen3-1.7B-q4f16_1-MLC); его применение проверяется на целевых браузерах до выпуска. Ответ ограничен по длине и содержит ссылки на использованные разделы. Ссылки строит приложение по `id` фрагмента, а не по произвольному URL из ответа модели. Неподтверждённый импорт, свойство или пример не должны подаваться как факт; при недостатке данных ответ предлагает открыть найденные разделы.

## Работа в браузере

Поиск доступен без WebGPU. Модель загружается только при первом запросе к помощнику, в отдельном Web Worker, с видимым прогрессом загрузки и возможностью отмены. После загрузки её файлы могут храниться в браузерном кэше; интерфейс не обещает, что кэш сохранится навсегда. Сайт не включает веса модели в свой статический пакет. Следовательно, для первого запуска нужен доступ браузера к месту размещения весов модели, а объём и время загрузки явно показаны пользователю до неё.

Если WebGPU недоступен, памяти недостаточно, загрузка прервана или генерация завершилась ошибкой, пользователь видит понятное состояние ошибки и те же результаты поиска со ссылками. Страница и поиск продолжают работать. История вопросов хранится только в текущей вкладке; серверного хранения диалогов нет.

## Размещение и стоимость

Статические сайты можно разместить в [Timeweb Cloud App Platform](https://timeweb.cloud/services/apps), используя отдельные маршруты или поддомены. Индекс — обычный статический файл документации. Серверных запросов к модели и базы данных нет. [Тариф фронтенд-размещения](https://timeweb.cloud/docs/apps/frontend-pricing) зависит от количества HTTP-запросов; домен оплачивается отдельно. Стоимость доставки весов модели через выбранный источник и доступность этого источника для аудитории проверяются перед публикацией. Веса нельзя незаметно положить в тариф сайта с ограниченным диском.

## Проверка результата

- Набор вопросов по опубликованным Button, Input, Tabs, теме и общим действиям должен находить правильный раздел среди первых результатов; отдельный набор вопросов о запланированных компонентах должен приводить к ответу «не найдено в опубликованной документации».
- Для ответов с генерацией вручную проверяются точность описания, публичные импорты, работоспособность ссылок и отсутствие утверждений, не подтверждённых найденными разделами. Отдельно проверяются вопросы на русском и английском.
- В целевых браузерах проверяются первый запуск, повторный запуск из кэша, отказ WebGPU, нехватка памяти, ошибка загрузки и отмена запроса. При каждой ошибке поиск остаётся рабочим.
- Перед защитой диплома модель и демонстрационные вопросы проверяются на том устройстве и в том браузере, которые будут использованы для показа. Если качество или время ответа неприемлемы, размер модели и длина контекста пересматриваются без изменения формата индекса и ссылок.

## Вне первой версии

Нет серверного инференса, бесплатного API с квотами, регистрации пользователей, постоянной истории чатов, индексации исходников и планов, автоматического выполнения кода и многошагового агентного поиска.
